| 2026-09-18 | M3-T01 (CI) | The Tauri template gives `src-tauri` `crate-type = ["staticlib", "cdylib", "rlib"]` | Cut to `["lib"]`. Linux and macOS never noticed. Mobile work brings both crate types back, along with whatever test layout that needs. |
| 2026-09-18 | M3-T02 (CI) | The generated `apps/desktop/src/types.ts` is compared byte for byte against what is committed, and Git for Windows checks text files out as CRLF | `.gitattributes` with `* text=auto eol=lf`, so the working tree is LF on every platform. Nothing stored changed — the repository was already all-LF — but without it the bindings test is stale on Windows and nowhere else, which is a failure about the checkout rather than about the types. Normalising the tree fixes the cause; special-casing the one file would have left the next generated file to find it again. |
| 2026-09-18 | M2-T08 (CI) | The second time a Windows path form has broken a test that passes everywhere else (after the verbatim-path entry of 2026-09-15) | A temp directory on a GitHub Windows runner arrives as a short 8.3 path (`C:\Users\RUNNER~1\AppData\Local\Temp\...`) and resolves to the long one (`C:\Users\runneradmin\...`). The CLI stores and prints the resolved form, which is right — `--project` has to find the Project whichever form was typed — so the tests were wrong to assert that what came back was the string they passed in. The fixture now keeps both: commands are given the folder *as typed*, and assertions are made against the canonical form. That tests more than it did before, because passing the unresolved form is exactly what someone typing a path does. |
| 2026-09-17 | M3-T05 | §7 says the UI detects gaps in `seq` and re-fetches with `list_events`; C13 says `seq` is global and the UI filters by Project | Those two together mean a gap cannot be detected per session: two Projects working at once interleave their events, so consecutive events in one conversation almost never have consecutive `seq`s, and "seq != last + 1" would refetch constantly. The feed tracks the global counter, and when *that* skips, every session being watched asks for everything after the last `seq` it actually holds. Events are held keyed by `seq`, so one that arrives twice — live and again in a refetch — is stored once, and the window's reaction to an event (a permission dialog, a running turn) is keyed by `seq` too rather than by counting, because a refetch can insert events before ones already held. |
| 2026-09-17 | M3-T04 | `03-architecture.md` §7 has `checkpoint_now` and `restore_checkpoint` as commands, with nothing said about whether an engine has to be running | Neither starts one. "Save a point I can come back to" and "put it back" are not an assistant's doing; making them start one would mean a folder could not be protected until an engine was installed and signed in. The IPC test is what found it: `checkpoint_now` failed with "Codex isn't installed". |

| 2026-09-17 | M2-T07 | `03-architecture.md` §6 has restore as a method on the turn engine, which holds an engine | Undo also exists as `turn::restore_without_session`, taking a store and a Journal and no engine at all. `eavery-cli undo` has no conversation open and must not have to start one — Undo is the button that makes everything else safe to try. | 2026-09-17 | M2-T07 | C13 says one turn per Project and a restore refused while a turn runs | Held in the turn engine, which is per process. | 2026-09-17 | M2-T07 | `06-plan-gate-permissions.md` §3.1 classifies a tool call from its `kind` and `locations`; `PermissionView` carries neither | `PermissionView` gained `kind` and `locations`, and the turn engine reclassifies every permission request before the user is shown it. Without this an edit outside the Project — which Undo cannot reach, and which §3.1 calls `Destructive` — would have been auto-allowed in direct mode as `Reversible`, on the strength of a guess made by the layer that does not know where the Project is. The M4-T02 `policy::classify` replaces the private function that does it now, adding the Connector registry it needs for the `outbound` flag. |
| 2026-09-17 | M2-T06 | `03-architecture.md` §8 gives the schema as seven bare `CREATE TABLE`s with no types enforced, no foreign keys, and the audit table's append-only rule stated as "no UPDATE or DELETE statements exist in the code for it" | The schema carries the rules instead. Every table is `STRICT`, so a column typed `TEXT` refuses an integer rather than handing one back later to a `parse` that cannot fail gracefully. `sessions`, `turns`, `events` and `checkpoints` have foreign keys onto their parents with `ON DELETE CASCADE`, and the store sets `PRAGMA foreign_keys = ON` on every connection — SQLite defaults it off, which would make the cascades decoration. `audit` has no foreign key at all, because a cascade from `projects` would be a DELETE: removing a Project forgets its conversation and keeps its decisions. The append-only rule is two triggers that `RAISE(ABORT)`, tested from a second connection that knows nothing about this crate; a rule that lives only in the callers holds until someone writes a new caller. Timestamps are RFC 3339 in UTC with nine fractional digits, fixed width, so `ORDER BY` on the column is chronological. |
| 2026-09-17 | M2-T06 | Nothing in the plan says how an event finds its `turn_id` on the way into the `events` table | `CoreEvent::turn_id()` was added and `append_event(session_id, event)` reads it off the event rather than taking it alongside: a caller that got the two out of step would write a transcript that cannot be reassembled. Two variants answer `None` — a restore happens between turns, and an engine's status is not about one — and a `CheckpointCreated` takes the turn from the checkpoint it carries, so the event and the checkpoint cannot disagree. |

| 2026-09-16 | M2-T03 | `05-git-journal.md` §3 says to decide which deltas get a text diff with `blob.is_binary()` | `git2::Patch::from_diff` does not answer `None` for a binary delta; it produces a patch whose body is "Binary files a/x and b/x differ" and which has no hunks. | 2026-09-15 | M0 (CI) | The Windows verbatim-path hazard `06-plan-gate-permissions.md` §3.1 warns about is not confined to `policy::is_inside`; it bit the ACP layer and the CLI first | `std::fs::canonicalize` returns `\\?\C:\...` on Windows.
